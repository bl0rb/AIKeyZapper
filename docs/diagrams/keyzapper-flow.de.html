Architektur · Sequenz · KeyZapper

So kommt der richtige Key ins richtige Projekt

Die App richtet einmalig Keys und Projektzuordnungen ein. Danach holt Claude Code den Key bei jeder Anfrage selbst über den Helper – pro Projekt, unabhängig voneinander, auch wenn die App geschlossen ist.

1 · Einrichtung (einmalig)

Key in den Schlüsselbund, Profil ins Projekt

Der Key geht nur per stdin an den Helper und landet ausschließlich im Schlüsselbund. Ins Projekt schreibt die App nur Verweise.

2 · Laufzeit (jede Claude-Anfrage)

Claude Code holt den Key selbst – pro Projekt

Beide Sitzungen laufen gleichzeitig und unabhängig; hier nacheinander dargestellt. Die App muss dafür nicht laufen.

Fehlerfall

Kein Rückfall auf andere Keys

Fehlt ein Key oder ist der Schlüsselbund gesperrt, endet der Helper mit Exit 66 bzw. 77. Claude schickt dann einen leeren Key, LiteLLM antwortet 401. Es wird nie ein anderes Profil oder der claude.ai-Login verwendet.

Keywechsel

Neue Sitzungen sofort

„Key ersetzen“ wirkt sofort für neue Sitzungen. Laufende übernehmen den Key nach Ablauf des Helper-Caches (5 min), nach einem 401 oder nach einem Neustart.

Geltungsbereich

Ganzes Repository

Claude liest die Zuordnung am Root des Haupt-Checkouts. Sie gilt damit auch für Unterordner und Worktrees. Geerbte ANTHROPIC_API_KEY/_AUTH_TOKEN werden neutralisiert.
